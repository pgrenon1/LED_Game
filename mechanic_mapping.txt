## Mechanic-to-code mapping

| Game mechanic | Code correlate | Alignment |
|---|---|---|
| **Either button launches a Pulse from its end** | Pins use `INPUT_PULLUP` in `setup()` (`LEDGame.ino:72-73`). `handleInput()` activates the left Pulse at pixel `0` or the right Pulse at pixel `NUM_LEDS - 1` (`LEDGame.ino:122-131`). | Implemented. Input is level-triggered, so holding a button relaunches its Pulse whenever that side becomes inactive. |
| **Pulses travel toward the opposite end** | `movePulses()` advances `leftPulsePosition++` and `rightPulsePosition--` at `PULSE_MOVE_INTERVAL_MS` intervals (`LEDGame.ino:133-145`). | Implemented. The interval is configured as 15 ms at `LEDGame.ino:26`; each Pulse deactivates after leaving the strip. |
| **Two active Pulses collide** | Collision is detected when both Pulses are active and `leftPulsePosition >= rightPulsePosition` (`LEDGame.ino:140-142`). `checkCollision()` derives the complete Collision Span (`LEDGame.ino:194-204`). | Implemented. A one-pixel meeting and a two-pixel crossing are both represented without directional bias. |
| **Pulses are visible while moving** | Active Pulses are rendered white in `drawScene()` (`LEDGame.ino:227-232`). | Implemented. |
| **The Target Zone is highlighted yellow** | `targetZoneStart`, `targetZoneEnd`, and `currentTargetZoneSize` hold Target Zone state (`LEDGame.ino:37-40`). `relocateTargetZone()` chooses its location (`LEDGame.ino:91-96`). `drawScene()` renders it yellow (`LEDGame.ino:207-212`). | Implemented with a Breathing Cycle. |
| **A Miss below the Progress Reset threshold displays a Miss Marker** | `handleMiss()` activates the Miss Marker at the Collision Span center when `missStreak < MAX_MISS_STREAK` (`LEDGame.ino:157-179`). `updateMissMarker()` renders it (`LEDGame.ino:235-243`). | Implemented as a three-red-pixel marker lasting seven render frames. |
| **A Hit runs the Hit Animation** | `handleHit()` calls `runHitAnimation()` (`LEDGame.ino:181-192`). The animation repeatedly fills the entire strip green (`LEDGame.ino:245-264`). | Implemented. |
| **A Hit advances Progress while the Target Zone is above minimum size** | `handleHit()` shrinks `currentTargetZoneSize` and increases `currentTargetZoneBreathingRate` while above `MIN_TARGET_ZONE_SIZE`, then relocates the Target Zone and removes both Pulses (`LEDGame.ino:181-192`). | Implemented without a numeric score. |
| **A Hit clears the Miss Streak** | `handleHit()` assigns `missStreak = 0` (`LEDGame.ino:181-183`). | Implemented. |
| **After a Hit, the Target Zone relocates** | `handleHit()` calls `relocateTargetZone()` (`LEDGame.ino:190`), which chooses a random location (`LEDGame.ino:91-96`). | Implemented. |
| **A Hit shrinks the Target Zone toward its configured minimum** | `handleHit()` decrements `currentTargetZoneSize` only while it is above `MIN_TARGET_ZONE_SIZE` (`LEDGame.ino:185-188`). | Implemented. The configured size exactly equals the rendered yellow-pixel count. |
| **The third consecutive Miss flashes the whole strip red** | `handleMiss()` increments `missStreak` and triggers `runProgressResetAnimation()` at `MAX_MISS_STREAK` (`LEDGame.ino:157-175`). The animation fills the strip red at alternating brightness (`LEDGame.ino:266-273`). | Implemented. |
| **The third consecutive Miss triggers a Progress Reset** | `handleMiss()` restores `currentTargetZoneSize`, `currentTargetZoneBreathingRate`, and `missStreak` before relocating the Target Zone (`LEDGame.ino:169-175`). | Implemented. |
| **A Progress Reset relocates the Target Zone** | `handleMiss()` calls `relocateTargetZone()` (`LEDGame.ino:175`), which picks a new random location (`LEDGame.ino:91-96`). | Implemented. |
| **Both Pulses are removed after either collision outcome** | `removePulses()` clears both active flags and positions (`LEDGame.ino:98-103`); `handleMiss()` and `handleHit()` invoke it (`LEDGame.ino:178,191`). | Implemented. |
| **Serial input can inject a Miss** | `handleSerial()` accepts `miss` and routes it through `handleMiss()` (`LEDGame.ino:105-120`). | Implemented as a diagnostic path using the same Miss and Progress Reset behavior as physical collisions. |

## Canonical game-state model

```mermaid
stateDiagram-v2
    [*] --> Waiting
    Waiting --> OnePulseMoving: one button pressed or held
    Waiting --> TwoPulsesMoving: both buttons active
    OnePulseMoving --> TwoPulsesMoving: other button pressed or held
    OnePulseMoving --> Waiting: Pulse leaves strip
    TwoPulsesMoving --> Hit: Collision Span overlaps Target Zone
    TwoPulsesMoving --> Miss: Collision Span outside Target Zone
    Hit --> Waiting: Hit Animation, advance Progress when possible
    Miss --> Waiting: Miss Streak below 3, show Miss Marker
    Miss --> ProgressReset: third consecutive Miss
    ProgressReset --> Waiting: red strip flash, restore Progress

```

The mapping reflects the canonical terminology and the current implementation.
